# Награды в существующем Phaser и фон поля — 09.11.2026

Три реализации проверены полным циклом и отклонены на стенде. Перенос наград в уже существующий GL-контекст уменьшил растровую работу и число наблюдавшихся слоёв, но ухудшил общие интервалы. Штатный Mesh2D batching Phaser не исправил результат. Дополнительный ограниченный перенос фона поля также проиграл. Продуктовой оптимизации и новой APK нет; плавность POCO остаётся открытой.

## Протокол и границы вывода

Linux, Chromium 141.0.7390.37, ANGLE Vulkan SwiftShader (программная графика), viewport 392×872, DPR 2.75, Phaser 4.2.1. [Фактический renderer и атрибуты](phaser-foreground/graphics.json). Это сравнение реализаций на стенде, не физическая приёмка Mali/Android и не измерение GPU execution time.

Каждый case запускается в новом browser context: два прогрева, два полных untraced эпизода по 8 секунд, отдельная 8-секундная CDP-трасса. Затем варианты проходят в обратном порядке. Другие браузерные проверки во время замеров не запускались. Во всех вариантах исходный legacy score glow, Festival DPR 1.5, прежние длительности/начисление/частицы. В каждом полном эпизоде проверяются score=shownScore=1574, pending=0, 148 созданных частиц, завершение эффектов и отсутствие JS/GL ошибок.

Всего 80 финальных полных эпизодов: 30 Extern, 30 Mesh2D, 20 фон поля. Это 32 untraced измерения, 32 прогрева и 16 отдельных трасс. Независимый Python-анализатор пересчитал из сохранённых интервалов все 7 протокольных метрик каждого из 32 untraced эпизодов (224 точных совпадения), проверил SHA-256 входных исходников и признаки фактической работы вариантов. Сырые интервалы прогревов не сохранялись; их независимый пересчёт не заявляется.

В таблицах средний RAF — среднее четырёх средних интервалов эпизодов, не физический FPS. Порог >33.4 мс применён после округления до 0.1 мс по существующему протоколу. Две цифры прямого и две обратного порядка показаны отдельно. Растровая работа — сумма worker wall из отдельных трасс, не длительность целого кадра; uniqueLayerIds — все уникальные ID за запись, не пиковое число одновременных слоёв.

## F5: общий GL-контекст через Extern

Исходный Phaser canvas остаётся дочерним элементом #board, но покрывает viewport. Камера поля сохраняет прежний физический квадрат; дополнительная сцена выводит подготовленные награды через GameObjects.Extern и тот же GL. Состояние renderer отдаётся/возвращается Phaser; shared renderer не очищает весь framebuffer. Исходный shake воспроизводится камерой по тому же native animation clock. При паузе награды отменяются, поле перерисовывается один раз до остановки loop.

В desktop исходный board backing **1024×1024** при CSS-стороне 360. Расширенный canvas 1116×2481 сохраняет его масштаб. Это увеличивает площадь framebuffer, поэтому включён отдельный контроль с таким же viewport canvas и исходными DOM-наградами. Счётчик подтверждает один живой GL-контекст на подключённых canvas во всех вариантах; created=2 учитывает также временную проверку возможностей Phaser и не означает два игровых renderer.

## F6: штатное пакетирование Mesh2D

Второй путь оставляет ту же геометрию и контроли, но награды становятся переиспользуемыми Phaser.Mesh2D с управляемыми CanvasTexture. Отдельных пользовательских GL shader/state restore нет. Атлас загружается один раз, невидимые quads пропускаются; submittedQuads означает переданные четырёхугольники, а не измеренное число draw calls. Ошибка ориентации UV исправлена до финальных визуальных проверок и замеров.

## F7: ограниченный перенос фона поля

Награды остаются DOM, canvas поля остаётся 1024×1024. Попытки непрозрачного canvas/обычного camera background закрыли сетку и изменили смешивание эффектов: визуальный gate не пройден, их производительность не сравнивалась.

Проверенный `gpu-bed-under` использует одну маску лунок и цвет с destination-over под существующими прозрачными эффектами. Во время shake сохраняется исходный CSS-переход, после shake фон временно принадлежит Phaser; в конце/при паузе возвращается CSS. Idle не добавляет отрисовку. Маска 1024² — оценка 4 MiB RGBA для CPU-изображения и примерно столько же текстуры, не измерение памяти процесса; подготовка на стенде 9.2–9.4 мс. В каждом полном эпизоде подтверждены activation/completion, 25–31 кадр работы и скрытая маска в конце.

| Вариант | >33.4 мс, прямой | >33.4 мс, обратный | Средний RAF, мс | Max, мс | Raster wall, мс | uniqueLayerIds |
|---|---|---|---:|---:|---|---|
| Исходный | 4 / 0 | 2 / 1 | 17.363 | 50.1 | 107.7 / 100.3 | 58 / 58 |
| GPU-фон после shake | 6 / 10 | 9 / 8 | 18.050 | 83.4 | 74.1 / 81.1 | 58 / 58 |

Phaser postrender: исходный 459/463/462/463, новый 448/441/444/438. Снижение raster wall примерно на четверть также не стало ускорением цикла. [Данные F7](phaser-foreground/bed.json); точные fingerprints сохранены в metadata, реализация — в дереве этого отчёта.

У Phaser 4.2.1 addBlendMode возвращает предыдущий индекс вместо добавленного. Прототип использует длину blendModes перед добавлением. Это совместимость нового helper, не найденная причина прежних рывков: продукт ранее этот пользовательский режим не использовал.

## Качество, жизненный цикл и регрессия

- Три пары размеров 392×872, 320×568, 872×392: DOM-геометрия поля/HUD совпала; масштаб физического поля сохранён. [Геометрия](phaser-foreground/geometry.json).
- По 14 фаз наград Extern/Mesh2D: максимальная средняя ошибка около 1.33/255, доля пикселей с отклонением >8 до 4.21%. Антиалиасинг и края отличаются; пиксельное равенство и продуктовая визуальная приёмка не заявляются. [Extern](phaser-foreground/extern-visual.json), [Mesh2D](phaser-foreground/native-visual.json).
- Семь статических фаз смены палитры поля: средняя ошибка ≤0.638/255. Восемь фаз с реальными clear FX: начало/shake и финал совпадают, в середине средняя ошибка ≤0.729/255, >8 максимум 0.1053%, максимальный канал 49. Visual-helper останавливает часы только для сравнения снимков; benchmark идёт с обычными часами. [Палитра](phaser-foreground/bed-visual.json), [FX](phaser-foreground/bed-fx.json).
- Шесть lifecycle проверок: пауза Extern/Mesh2D/фона; холодная отмена Mesh2D/фона; принудительная потеря/восстановление GL фона с тем же canvas/context и работающим последующим clear. При паузе счёт 1574 виден, DOM-наград нет, renderer callbacks остановились. Укороченные прерванные проверки не входят в 80 полных эпизодов. [Данные](phaser-foreground/lifecycle.json).
- 231 unit-тест (34 файла), production build/typecheck, assets:check и четыре действующих browser сценария Festival/score-glow прошли. Shipping main.ts, BoardScene.ts, Festival, CSS, версии и Android не менялись. Интеграция существует только в локальном Vite transform; production bundle не содержит study globals/renderer/маску.

Прототипы изолированы и отклонены по производительности; работа по всем resize/context recovery сценариям наград не завершалась как для релиза. Android/APK в этой итерации не собирались. Новое физическое испытание пользователя не требуется для выдачи этих путей как исправления: основания для такой выдачи нет.

## Воспроизведение

Сначала выбрать точный commit F5/F6 либо дерево отчёта F7; зависимости из package-lock.json. Каждый benchmark сам делает два порядка, прогревы, измерения и отдельные трассы. Не запускать рядом другие браузерные тесты.

```sh
# F5
STUDY_VARIANTS=original,viewport,phaser STUDY_OUTPUT=/tmp/phaser-extern node scripts/study-foreground-benchmark.mjs
# F6
STUDY_VARIANTS=original,viewport-native,phaser-native STUDY_OUTPUT=/tmp/phaser-native node scripts/study-foreground-benchmark.mjs
# F7
STUDY_VARIANTS=original,gpu-bed-under STUDY_OUTPUT=/tmp/phaser-bed node scripts/study-foreground-benchmark.mjs
python scripts/summarize-renderer-study.py /tmp/phaser-bed/result.json /tmp/phaser-bed/summary.json --source-root .
node scripts/study-renderer-lifecycle.mjs
node scripts/study-board-composite-visual.mjs
node scripts/study-board-composite-fx.mjs
npm test
npm run build
npm run assets:check
npx playwright test e2e/festival.spec.ts e2e/score-glow.spec.ts --workers=1
```

Новые visual/lifecycle helpers пока используют scratch-путь автора для результатов; при переносе изменить только их output path. Сырые трассы/скриншоты/интервалы не добавлены в git; здесь компактные агрегаты и входные fingerprints. Снижение ресурсного счётчика без улучшения полного цикла по-прежнему не закрывает проблему плавности.
