# Preview 0.17: баннер, межстраничка и rewarded

## Поведение
- Баннеру выделено место в портрете и альбоме. Пустая область совпадает с фоном. До загрузки SDK сообщает адаптивную высоту, JS увеличивает резерв и повторяет измерение; no-fill не схлопывает поле. Native-вид скрывается в диалогах, обучении, фоне и fullscreen. На повороте старая геометрия инвалидируется. Размеры считаются от WebView/root, не слепым умножением CSS на density.
- Межстраничка возможна только по «Ещё раз» после проигрыша. Нет показа на запуске, Back, Resume, во время хода или рестарте незавершённой партии. Минимум две завершённые партии и 180 секунд активной игры после предыдущего fullscreen-намерения; максимум три возможности межстранички за час активной игры. Это консервативнее ограничения за реальный час и защищено от перевода часов. No-fill/сбой может израсходовать возможность, но не задерживает переход до будущей загрузки. Новая партия сохраняется до обращения к SDK; уже показанный fullscreen не прерывается таймером. Pre-show deadline 15 секунд принадлежит native-мосту.
- После исчерпания бесплатных подсказок открывается явное предложение «Посмотреть рекламу — получить 3 подсказки», доступен выход без рекламы. Награда — три сохраняемых кредита, без рекламы при каждом их использовании. В браузере без native SDK показ честно недоступен.
- Второй шанс доступен один раз на проигранную партию, только если есть полезная зона 3×3. До согласия показана точная область. Приоритет: количество допустимых размещений оставшихся фигур, число удаляемых клеток, y/x. После подтверждённого просмотра очищается подготовленная зона, очки/лоток/RNG сохраняются, серия сбрасывается. Закрытие объявления без reward ничего не выдаёт.
- Поздний revive не заменяет новую партию: сохраняется право вернуться к исходному полю. Кнопка в паузе/результате требует подтверждения замены текущей партии. Уже полученный второй шанс отмечен на результате.

## Доставка наград
До show сохраняются intentId, gameId/revision и исходный snapshot; для revive — подготовленный эффект. Native `onRewarded` синхронно записывает квитанцию в SharedPreferences до уведомления JS. Event/show-result/startup recovery проходят одну очередь. Effect и receipt id фиксируются одной транзакцией current+backup через общий ProfileStore; затем acknowledge удаляет только эту native-квитанцию. Ошибка записи не подтверждает удаление; ошибка acknowledge допускает безопасный повтор. Дубли token и разные token одного intent не удваивают эффект. Неизвестная квитанция остаётся native-side и сообщает о проблеме, не перенаправляется в чужую партию.

Native хранит очередь, а не единственный перезаписываемый token. Новый rewarded не предлагается при необработанных native-квитанциях. Незавершённые intents/ledger не обрезаются произвольным лимитом. Рост истории — известная цена текущего локального протокола; очистку можно делать лишь после доказанного окончания replay horizon. Если процесс убит до SDK reward, подтверждения нет. Ошибка самого native disk commit показана отдельно и не объявляется успешным начислением.

## SDK и конфигурация
Yandex Mobile Ads `8.6.0`, Android main thread. Официальные источники проверены 28.10.2026:
- https://ads.yandex.com/helpcenter/en/dev/android/quick-start
- https://ads.yandex.com/helpcenter/en/dev/android/adaptive-sticky-banner
- https://ads.yandex.com/helpcenter/en/dev/android/interstitial
- https://ads.yandex.com/helpcenter/en/dev/android/rewarded

Debug 0.17 использует только `demo-banner-yandex`, `demo-interstitial-yandex`, `demo-rewarded-yandex`. Release требует три собственных значения `YANDEX_BANNER_AD_UNIT_ID`, `YANDEX_INTERSTITIAL_AD_UNIT_ID`, `YANDEX_REWARDED_AD_UNIT_ID` из окружения; build guard не допускает пустые/demo ID. Значения в git не сохранены. Production-публикация не выполнялась.

SDK добавляет рекламные зависимости и разрешения; декларации данных/privacy должны быть сверены с итоговым merged manifest и реальной release-конфигурацией до RuStore. AppMetrica/собственная продуктовая аналитика в этом пакете не подключены: native пишет технические события в Logcat. Аудиофокус Android и реальные показы остаются аппаратными проверками.

## Проверки
- 66 unit-тестов проходят: правила, сохранения, новый протокол рекламы, точный revive, дубли, late delivery, повреждённый подготовленный эффект, отказ записи и acknowledge, блокировки, cooldown и геометрия баннера.
- Полный локальный браузерный прогон: 70 сценариев. После уточнения перехода и preview повторены затронутые группы (24 сценария) и рекламные сценарии (9). Production build проходит.
- Браузерный mock подменяет модуль только через Playwright route; production-код не содержит глобального переключателя mock/native.
- Скриншоты 320×480, 568×320, 390×844 просмотрены. На коротком экране тело revive-диалога прокручивается, кнопки доступны. Превью использует реальные цвета клеток, зона читается до согласия.

Эти результаты не доказывают реальный native banner, доставку тестовых объявлений SDK, отсутствие перекрытия системных inset на устройстве или заработок. Для телефона: портрет→альбом→портрет, no-fill/сеть, reward→закрытие, фон/возврат, закрытие без reward, kill после reward и восстановление. Native скриншоты и физический плейтест пока отсутствуют.

CI, сертификат и хеш APK будут добавлены после Android-сборки.
