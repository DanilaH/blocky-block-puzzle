# Preview0.53 — размеры окна вне рисования эффектов

## Правка

По физической трассе0.52 в Atmosphere/Festival убраны viewport reads из покадрового draw/очистки. Сохраняются CSS width/height и DPR (прежний предел1.5). Размеры/2D backing store обновляются по resize и началу эффекта; Atmosphere обновляет их при возобновлении после паузы/calm, Festival — перед burst. Resize по-прежнему останавливает старые частицы и SVG-кольцо. Глобальные window APIs не переопределяются. Геометрия, цвета, количество частиц, тайминги, режимы смешивания, основной WebGL canvas, flow-v4 и native tracing не изменены.

Это удаление конкретной подтверждённой лишней работы, **не утверждение об устранении всех лагов**. Ожидания native graphics из0.52 пока требуют повторного физического замера.

## Проверки

- 221 unit, build, assets:check.
- 12 целевых browser-сценариев:6 старого автозамера,4 короткого теста,2 нового viewport/lifecycle. Новые проверки заставляют viewport getters бросать исключение во время draw; отдельно проверяют поворот, очистку старого SVG и возобновление при изменённых width/height/DPR без resize event.
- [Точное сравнение картинки](viewport-053/pixel-parity.json): seeded RNG/одинаковое время, пять фаз17/400/650/1100/1800мс; оба2D canvas и SVG задней дуги полностью совпали с0.52. Canvas588×1308 при392×872/DPR2.75 и cap1.5. Проверяется именно картинка двух изменённых слоёв; полный native screenshot не выдаётся за проверенный.
- [Реальный интегрированный mobile-прогон](viewport-053/integrated-comparison.json): baseline/candidate/candidate/baseline, по3 очистки. Baseline загружает исходные0.52 модули двух эффектов; candidate использует обычные0.53 исходники. Глобальных getter overrides нет. Скрипты [comparison](../../scripts/probe-viewport-053.mjs) и [pixels](../../scripts/verify-viewport-053-pixels.mjs).

Новый fixture-тест сначала показал неверные размеры из-за отсутствующих CSS для полноэкранных canvas на тестовой странице; fixture приведён к fixed/100% и обе проверки прошли. В приложении соответствующие стили уже были. Черновой A/B запуск шёл параллельно прочим локальным browser-тестам и не используется для выводов; итоговый прогон повторён отдельно.

Все software-эпизоды A/B записывались под CDP tracing: имена warmup/untraced/traced унаследованы от APK-сценария и **не означают**, что CDP был выключен в untraced. Результат о forced layouts не равен приросту FPS на Mali. На desktop/mobile эмуляции backing основного поля1024²; на физическом POCO0.52 —896². Состояние/очки/тема всех12 ходов совпали (1574/тема5).

В окне320–1400мс итоговый baseline дал175/175 принудительных style/layout пересчётов и78.244/76.638мс; кандидат11/11 и7.994/8.501мс. Большого выигрыша по rAF на software graphics не получено: untraced17/17 интервалов>25мс у baseline против16/15; traced15/16 против16/16. Эти короткие серии не подтверждают изменение FPS на телефоне.

Дополнительно проверено, не переехала ли та же работа в обычный lifecycle: [одна диагностическая пара](viewport-053/total-style-check.json). Все Blink.Style.UpdateTime в окне снизились86.784→78.551мс (около9.5%), Document::recalcStyle83.170→76.046мс, тогда как rAF callback time140.831→57.161мс. Значит, **значительная часть style-работы действительно откладывается за пределы JS, а не исчезает**. Нельзя называть уменьшение forced layout на90% уменьшением общей нагрузки или ускорением игры на90%. Одна пара с CDP недостаточна для общего FPS-вывода (rAF счётчики нестабильны); остаётся проверить физический эффект и native waits. В скриптах также изолированы cacheDir двух Vite-серверов, чтобы cold dependency optimizer не мешал диагностическому запуску; неудачный дополнительный запуск до этой изоляции не использовался.
