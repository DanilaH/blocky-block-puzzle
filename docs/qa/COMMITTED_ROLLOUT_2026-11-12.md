# D84 — продолжение согласовано с прогнозом, игровой выигрыш не подтверждён

**Техническая согласованность PASS; поведенческая приёмка REJECT.** В игру
вариант не переносится. APK0.63/director-v2 и production-файлы прежние.

Проверена одна причина потерь D83: прогноз продолжал v2, а исполнение заново
выбирало альтернативы. D84 после выбора текущей тройки оставляет следующие
две выдачи v2, затем снова вызывает тот же селектор. Подбор C1/v2, ансамбль
ботов,9-ходовой прогноз, guards, оценки и RNG-правила D83 не изменены.

## Что именно закрепляется

Закреплён поставщик продолжения, а не будущие фигуры/координаты. Каждый новый
лоток v2 строит по фактическому полю после действий игрока. Полная очистка
не отменяет оставшиеся две выдачи: прогноз D83 тоже продолжает v2 через
награду с реальным обновлением состояния. Все допустимые действия игрока
остаются доступны. Это явный офлайн-счётчик двух refill, не реализованная
миграция сохранения и не доказательство необходимости глобальных фаз.

[Протокол](committed-rollout/protocol.md) заморожен до первого запуска.
Изменения исторических D79–D83/их данных не делались.

## Согласованность действительно исправлена

- Все55 прежних matched held-v2 случаев D83 повторились по действиям и полному
  финальному состоянию. Пример3301002/.125 снова очищает поле на9-м ходе.
  Эти известные данные не входят в новые показатели успеха.
- Для654 новых контекстов решения отдельно исполнены четыре модельных пути
  выбранной тройки:2616 fork-прогонов. Они точно совпали с соответствующим
  сохранённым9-ходовым прогнозом по ходам и финальному состоянию, включая смерти.
- В полном strong-пилоте104 достаточно длинных участка между решениями
  совпали с прогнозами. Расхождений0. Последние неполные окна при cap240
  исключены из этого сравнения и не объявлены успешными/завершёнными.

Следовательно, сохранённый дефект «оценили v2, затем сами заменили продолжение»
для этого расписания устранён. Это согласованность с данными модельными
траекториями, не точное предсказание людей/произвольного случайного выбора.

## Независимые проверки

- Все1058 контекстов заново построены из frozen v2/C1; прогнозы всех кандидатов,
  guards и выбор проверены публичными правилами/неизменёнными игроками.
- 111265 прогнозных действий без повторного счёта совместных префиксов,
  6077 фактических ходов,471 старый regression-ход,22996 fork-действий,
  96 source-ходов и42783 proof-действия повторены независимо клеточными правилами.
- Исполнение расписания проверено отдельно по номеру выдачи modulo3, а не
  повторением счётчика реализации. Strong-окна сопоставлены до следующего
  выбора, поэтому замена лотка на следующей границе не маскирует расхождение.
- 313 unit/49 файлов и production build прошли. Сохраняется прежний warning
  Phaser chunk-size.157 src/Android/package-файлов побайтно прежние.
- Новый игровой browser/worker/Android/телефон не запускались. Runtime-cost
  оптимизация не начиналась, т.к. behavior gate отрицательный. Wall-time в
  данных относится к общей офлайн-среде, не к Android.
- Счётчик продолжения не входит в production save schema. Обновление/restore
  такой политики на телефоне этим экспериментом не проверены.

## Решение

Не переносить D84 в игру и не увеличивать глубину/число коэффициентов ради
спасения этого wrapper. Технический дефект D83 закрыт; его исправление не дало
устойчивого наградного результата. Это не отрицание всех локальных/rollout
выдач, не доказательство необходимости глобального директора и не обещание,
что ещё один уровень поиска решит проблему.

Рекомендованный следующий шаг — уже подготовленное человеческое сравнение
существующих flow-v4/v2 на0.63: [порядок и форма наблюдений](dealer-architecture/human-comparison.md).
Нужен конкретный повторяемый момент, где игрок теряет понятную награду/контроль,
чтобы следующее вмешательство решало наблюдаемую проблему. Старые и новые
ботовые результаты не подменяют такое наблюдение. POCO и release cohort открыты.
