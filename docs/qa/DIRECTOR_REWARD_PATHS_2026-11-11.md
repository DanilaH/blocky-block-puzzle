# D76 — несколько окончаний подготовки: технически проверено, баланс не принят

Отдельный исследовательский `director-v5`, основан на рабочей ветке
`feat/director-forgiving-2026-11-11` / `b51242f`. Default и APK0.63/director-v2
сохраняются. Новую APK на отрицательном балансе не выпускали.

## Что изменено

- Подготовка строится через локально привлекательные промежуточные размещения,
  а не произвольный идеальный маршрут. Конструктор не импортирует игроков.
- Для тройки оцениваются разные окончания: три первых × три вторых × до трёх
  последних ходов. Совпадающие поля объединяются. Чтобы сохранить подготовку,
  нужны минимум три разных поля и положительное доказательство награды минимум
  в60% этой ограниченной выборки. Это не вероятность человеческого успеха.
- Хранятся до12 конкретных полей/развязок. Каждый положительный путь и путь к
  его исходному полю воспроизводятся публичными правилами. Диагностический
  список содержит также проверенные окончания без найденного пути: это unknown,
  а не доказательство невозможности награды.
- Компактный поиск развязки за1–3 фигуры заполняет занятые строки либо столбцы,
  с индексом последней фигуры. Это ограниченный класс целей, не полный solver.
- Подготовленная возможность получает приоритет над очередной нагрузкой;
  фактическая награда отменяет её. На реальном поле payoff проверяется заново.
- Прежние защита вторых ходов, честный fallback и общий лимит24000 сохранены.
  Новая версия имеет отдельное состояние в профиле, worker и revive; старые
  партии не мигрируют. Реклама, часы, рекорд и стиль бота в политику не входят.

Пять инженерных вариантов сохранены отдельно. Выбран C3, затем до контроля
зафиксирован [протокол](director-reward-paths/protocol.md). Новые development
1441001–1441008 и confirmation1461001–1461008; пять неизменённых игроков,
две политики, лимит360. Код/критерии между выборками не менялись.

## Что именно осталось

У bounded было лишь две выдачи с сохранённой широкой подготовкой на16 партий.
Из457 законченных оценённых троек реальное окончание попало в выборку в278
случаях; положительный путь награды для фактического окончания был найден только
в20. Отсутствие найденного пути не доказывает невозможность: класс поиска узкий.

Ни одна подготовленная возможность не вытеснена другой фазой. Значит,
приоритет payoff исправлен, но сам конструктор редко создаёт подходящую широкую
возможность для неточных действий. Сертификация хорошего кандидата не заменяет
его построение. Несколько сохранённых endpoint решают хрупкость одного точного
поля только там, где хорошие endpoint уже получаются.

Следующий инженерный шаг — разбирать фактические окончания из
[outcomes.json](director-reward-paths/outcomes.json), различать пропущенную
поиском развязку и плохую подготовку и использовать цель награды внутри
ветвящегося построения. Не продолжать подбирать геометрические коэффициенты
по этим контрольным seed и не считать одну успешную выборку приёмкой.

## Регрессия и границы

303 unit /46 файлов, TypeScript/production build и assets-check прошли.
Первый полный46-worker запуск под одновременными benchmark/replay/browser дал
таймаут одного неизменённого rhythm-теста; полный повтор с maxWorkers4 прошёл
без изменения теста или его timeout.

8 browser:24 настоящие постановки v5,24 v4,36 v2, worker/refill, resume,
отмена перезапуска, ошибки записи, конфликт writers и закрытие с транзакцией.
Новая unit-регрессия также проверяет однократный revive и три recovery refill.
Все416 исторических партий /79 116 ходов сохранили прежние финальные GameState
SHA256. Replay новых160 партий заново вычислил решения игроков, выдачи,
события и финальные SHA. [Проверки](director-reward-paths/checks.json).

Чистое время refill на общем Node-стенде: медиана9.74→9.18мс, p9517.31→17.67мс.
Параллельные проверки влияли на CPU; это не изолированный performance benchmark
и не измерение POCO. Новый Android/native-прогон не проводился. Лаг полной
очистки не объявляется исправленным. Человеческий баланс и релизный объём
1000 seed/player/policy остаются открытыми.

node scripts/director/reward-benchmark.mjs

запускает контроль. Все перечисленные scripts работают из корня репозитория.
