# Preview 0.46: запись реальной партии для калибровки

Это инструментарий, а не принятый новый баланс. Выдача flow-v4, очки, эффекты и рекламные правила не изменены.

## Как использовать

Пауза → Ещё настройки → Запись партии для разбора → Начать запись. Закрыть паузу, играть как обычно. Затем в том же разделе выбрать «Выгрузить запись партии» и передать JSON для разбора. Можно начать посреди партии; такой фрагмент не объявляется полной сессией. Подсказки помечаются отдельно.

Запись добровольная, по умолчанию выключена. Автоматической отправки нет. Она хранится только в памяти текущего запуска: **выгрузить до закрытия приложения/перезагрузки страницы**. Обычное сворачивание не очищает её, но выгрузка процесса системой очищает. При экспорте запись останавливается; неудачная выгрузка не удаляет данные, можно повторить. Отдельная кнопка удаляет запись. При достижении лимита 800 КБ запись останавливается без удаления начала; нужно выгрузить и очистить перед новой.

## Содержимое и корректность

Начальные состояния, только успешно сохранённые ходы, контрольные суммы, время активного игрового экрана и общее время, отметки подсказок. Новые партии, revive и прочие изменения состояния отделены контрольными точками. Нет профиля пользователя, рекламных идентификаторов или настроек аккаунта. Android переиспользует системное меню отправки; файл `blocky-play.json`. В браузере скачивается `blocky-play-0.46.json`.

Запись идёт после успешного атомарного сохранения, не вызывает генератор или поиск и не пишет на диск после каждого хода. Время между ходами включает ввод, вычисление и сохранение, поэтому это не чистое «время раздумий». Неактивный экран/пауза/реклама исключены из активного времени.

Офлайн-импорт проверяет схему, временную последовательность, состояния и воспроизводит каждый ход настоящими правилами. Несовпадение останавливает разбор. Контрольные точки — явные границы: незаписанные переходы между ними не объявляются проверенными.

Анализ сравнивает выбор игрока с clear/space/two/three на том же поле. Отличие от бота не называется ошибкой. Отдельно отмечается доказанный тупик, только если в этой позиции существовал другой продолжаемый ход. Unknown при исчерпании бюджета не считается проигрышем. Ходы с подсказкой исключены из показателя самостоятельных ошибок.

```sh
node scripts/calibration/analyze.mjs blocky-play.json report.json
```

## Проверки и текущие ограничения

Локально: 201 unit; build; 8 целевых browser-тестов, включая настоящую постановку через UI, JSON-выгрузку, точное воспроизведение и отсутствие несохранённого хода после ошибки IndexedDB. Сохранённый `synthetic-ui-analysis.json` — **автоматизированный UI-сценарий, не человеческий плейтест**. Реальный журнал ходов в доступных найденных материалах не обнаружен; калибровка навыка/длины партии не выполнена, целевые значения не придуманы.

Полный CI [42269275617](https://github.com/DanilaH/blocky-block-puzzle/actions/runs/42269275617) прошёл: 201 unit, 130 browser, Android unit/build. APK из PR: версия 0.46, v2-подпись проверена и совпадает с 0.45, 78 production-файлов совпали с локальной сборкой. Артефакт 13529461406; SHA256 и manifest — в `play-capture-0.46/apk-verification.json`. Физическое меню отправки Android и влияние записи на реальном устройстве пока не проверены. Измерения CPU в облаке не заменяют FPS на телефоне.

Дополнительно: 1000 синтетических ходов точно воспроизведены, 135 937 байт, recorder-only p95 0,109 мс на облачном Node; это не Android/FPS. Первый CI остановился на общем пятисекундном лимите старого теста 25 seed: те же 25 случаев разнесены по отдельным тестам без сокращения проверок, поэтому счётчик unit вырос на 24.
