# Opening-stage pilot — fixed before bot results

The protected frontier failed its CPU gate on both existing human captures:820 hash-verified moves,271 refill positions, only6 changes; p95 ratio1.542 above1.25. Its planned full trajectory experiment is stopped before bot development/confirmation. No threshold tuning, no production integration.

Catalog enumeration supplies a stronger structural limit: area24 has exactly one family composition (O3,O3,R6), and area18 with the opening cap of6 per piece has exactly one (R6,R6,R6). A selector preserving area cannot diversify these compositions. This is about this catalog, not a universal impossibility for another generator/catalog.

## New, narrower product hypothesis

Develop the opening stage separately from global adaptation. One varied initial tray, then unchanged flow-v4. Sample existing per-orientation catalog weights restricted to the existing maximum6 cells, reject all-one-family triples, require a complete witness within5000 checks; at most32 draws, then original fallback. The opening-only stream uses the game seed xor ASCII `open`; the persisted future RNG is exactly the baseline RNG. No clocks, ads, session counters, skill estimates or forced defeats. Saves, score and production default are unchanged.

This intentionally permits a different initial total area. It is a new objective, not a claim that the protected frontier passed. Real play after the first move may diverge. Existing human actions are not replayed against the changed opening.
