## Revive: проверка исправления и совместимости

Человеческий дефект: baseline `(5,4)` заменяется на `(5,5)`; синтетический —
`(3,0)` на `(3,4)`. В двух корректных человеческих случаях прежние `(2,5)`
и `(2,3)` сохраняются. Положительные witness выполняются настоящим applyMove.
После первого хода двухфигурного остатка recoveryDeals ещё 3; после завершения
старого лотка становится 2. То же проверено для новой политики.

Награда по-прежнему одна, 3×3, тот же лоток/счёт, сброс серии и 5 секунд.
Поиск выполняется до установки deadline. Его влияние на фактически видимое
окно телефона не измерялось. Сохранённые старые планы без selector tag
принимаются и применяются без повторного выбора; earned/available права,
поздняя исходная партия и дедупликация receipt сохранены. Нулевой бюджет proof
даёт baseline-unknown, а не утверждение о невозможности. Все proofs делят
общий allowance; 36 независимых больших budgets не используются.

## Один кандидат: результат, а не автоматическое принятие

[Протокол](commercial-iteration-2026-11-13/PROTOCOL.md) зафиксирован до сравнения.
Кандидат не меняет площадь заменяемого слота и две другие фигуры. Поддерживающие
роли сохраняют число линий и найденные исходным witness полные очистки;
если был тактический certificate, требуется новый certificate того же вида.
Семейства ранжируются по ограниченной истории последних четырёх лотков;
поворот не является новой формой. Нет подходящего слота/доказательства —
исходная тройка, диагностическая причина и bounded fallback. Последняя причина
сохраняется в состоянии только новой политики. Старый v2 не переопределён.

Все 663 исторических хода повторены с точными hash. Для 88 исходных выдач
восстановлены реальные pre-deal состояния, включая начальные seed обратным
xorshift; точное совпадение исходных v2 лотков/RNG проверено. Новый кандидат
меняет 16/88: 43 no-equal-area-slot, 15 already-diverse, 13 budget, 1 no-role-proof.
Все 88 witness / 264 размещения проверены также независимым клеточным обходом.
45 равноразмерных возможностей из входного исследования не объявляются 45
сохранёнными тактическими задачами: ограничения кандидата строже простой
геометрической разрешимости.

Новые seed 4101001–4101008: 48 запусков, 27 ended / 21 censored на 180 ходах.
В бот-сравнении revive не использовался; его guard проверен отдельно и одинаков
для обеих политик. Это инженерные модели, не новые человеческие участники.

| Модель | Малые формы: v2 → кандидат | Ходы: v2 → кандидат | All-clear: v2 → кандидат |
|---|---:|---:|---:|
| bounded | 6,7% → 16,2% | 321 → 208 | 5 → 3 |
| three | 15,0% → 17,6% | 1440 → 1440, все censored | 262 → 71 |
| lapse | 11,3% → 17,3% | 1040 → 817 | 66 → 22 |

Заранее заданные инженерные gates по линиям/продлению/поражениям lapse прошли.
Но bounded партии стали короче, а награды сильного игрока заметно реже.
Равная площадь не означает равную сложность. **Решение: технический кандидат
для человеческой пробы; баланс HOLD, default и rollout не включены.** Новый
кандидат или ослабление gates после результата не создавались.

## Измерения и деньги

Старый game_end сохраняет прежний смысл исторического события. Новые run_failed
считают каждое поражение, run_closed — финальный эпизод, run_reopened — позднее
earned-восстановление с новым episodeIndex. При восстановлении сохраняются
известные суммарные activeMs/maxStreak и источник intent; для старых прав без
контекста неполная длительность не превращается в полную.

Первый ход, старый лоток, следующая тройка и новое поражение после revive имеют
разные стабильные event IDs, даже если два milestones случились одним ходом.
Прогресс сохраняется атомарно; failed save не продвигает flags. Продолжение
исходной партии и available-награда различаются. Финальная interstitial
возможность оценивается один раз на episode, сохраняет все одновременно
нарушенные условия и состояние запроса; ready=false не переименовывается в
no-fill. Поздняя награда в ожидании readiness не закрывает живую игру и не
вызывает interstitial посреди неё. Численные рекламные caps не изменены.

Кабинет/фактическая выгрузка недоступны. Выбран ручной native AdRevenue route
для точного placement/offer/intent context. Основной расчёт принимает только
SDK AdRevenue export с `source=blocky_ilrd_v1`; автоматический поток и custom
диагностика не суммируются. Общие dashboard totals без фильтра ещё не сверены.
Native callback передаёт деньги без JS memory queue; Java tests проверяют
null/zero/decimal/currency/precision, но не доставку SDK/кабинета.

Событийный JS transport остаётся bounded best-effort, а не exactly-once.
Assignment сохраняется до отличающегося поведения и повторно сообщается
стабильным ID при запуске; SDK delivery/полнота экспорта требуют сверки.
Деньги — факты impression, награда — earned/applied, одно не заменяет другое.

Ручная проба не создаёт audience assignment. Аудиторный rollout выключен.
Существующая партия не мигрируется; existing enrollment — с новой партии.
В уже назначенной аудитории ручной selector блокирован, группа не меняется.
Отключение кандидата/смена config возвращает безопасный control, оставляя
исходную принадлежность для intention-to-treat анализа.

[Формат выгрузки, команды и ограничения расчёта](../../scripts/commercial/README.md).
[Синтетический пример отчёта](commercial-iteration-2026-11-13/example-metrics/report.md)
и его график не являются выручкой или доказательством uplift.

## Длинная сессия и установленная граница

Chromium software renderer, 603 секунды, 203 синтетических clear/drag/pause/
restart цикла, 40 поражений, 55 hints. Ошибок 0. Сцена 1249 объектов и 768
плиток неизменна; 3 canvas. После settle animations/voices/sparks/clockJobs = 0.
Heap после GC 26,45 → 27,68 МБ; последние шесть точек 27,61–27,70 МБ.
Это не доказательство отсутствия утечки на телефоне. Здесь использовалась
одна загруженная worktree-версия UI; последующие не визуальные доработки
проверены отдельно. Это не before/after сравнение производительности.

Хвостовой RAF p95 33,4 мс. Фазы стенда: save mean 17,9/max114 мс,
placementRender mean1,07/max39,5 мс, reviveSelection mean1,73/max19,2 мс.
Дорогие refills отдельно измерены в кандидатном cohort; синтетические UI
fixture-ходы сами по себе почти не требуют поиска выдачи. Ранние/поздние
окна сохранены; межплатформенного SLA из этих чисел не выводить.

Жалоба владельца на лаг остаётся открытой: этот сценарий не воспроизвёл
монотонное накопление объектов и не установил причину телефонного дефекта.
Renderer/праздник не урезались. Файл длинной сессии и локальный поздний отрезок
реальной записи позволяют повторить диагностический сценарий; физический
профиль, SDK ad-return, thermal/GPU/heap нужны отдельно.

- Historical replay/cell checks, 88 composition regressions и 48 frozen

**Новой APK нет.** Проверка сборочного задания сообщает: нет Android platform36/
build-tools36.0.0, полной JDK-конфигурации командных инструментов, прежнего
ключа подписи и отдельного APPMETRICA_TEST_API_KEY. Не создан новый случайный
signer, production key не подставлен. [Точный blocker JSON](commercial-iteration-2026-11-13/build-blockers.json).
Воспроизводимая команда: `python3 scripts/commercial/build-preview.py --output
/absolute/path/blocky-0.64-preview.apk`. Существующий CI Android job использует
тестовый secret и сохранённый preview signer; его запуск на новом commit ещё
не выполнен. Тестовая упаковка теперь запрещена без отдельного корректного
test key; это проверка конфигурации, не доказательство принадлежности кабинета.

Обычный Git push не выполнялся. Автоматическая проверка отклонила outbound
dry-run как неавторизованную передачу метаданных ветки/репозитория. Обход не
применялся. Изменения сохраняются локальным Git и цельным bundle D79–D87.
