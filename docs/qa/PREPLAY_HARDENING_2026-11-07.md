# Техническая доводка перед человеческим плейтестом — 07.11.2026

## База и статус

База — `cf16c37`, PR #2, доступная preview 0.46 плюс изоляция сбойного расчёта хода. Предыдущий пакет прошёл GitHub Actions `42362507640` и `42362490610`, включая Android unit/build. Это подтверждение сборки, не установки или реального рекламного SDK на телефоне.

GitHub-ветки проверены повторно: локальных изменений 0.47 из прежнего окружения по-прежнему нет. Данный пакет нужно переносить поверх них, сохраняя новые постановки очисток, аудио и исправление похвалы. Версия приложения здесь не повышена, новый пользовательский APK не выдаётся.

## 1. Подсказки: старый запрос мешал новому

В Classic `onmessage` сначала завершал глобальный текущий worker, а только затем проверял generation. В обоих режимах старый `onerror` вызывал общую отмену. Если отменить запрос через паузу, начать новый и доставить уже поставленный в очередь callback прежнего запроса, он мог завершить новый поиск.

До изменения два браузерных regression на исходных `main.ts` и `adventure/view.ts` из `cf16c37` провалились: счётчик terminate у нового worker стал 1 вместо 0. Это управляемая инъекция редкой гонки, не частота её появления на устройствах.

Теперь обработчики проверяют идентичность worker и generation до любых действий. На отмене и получении результата очищается внешний таймер; зависший поиск завершается через 5 секунд. Отказ конструктора Worker, postMessage, onerror и onmessageerror возвращает возможность повторить. Списание остаётся после проверки актуальности и успешной атомарной записи; не переносится в начало поиска.

12 новых browser-сценариев: timeout/crash/messageerror/send/construct для двух режимов, плюс запоздавшие message/error после отмены и нового запроса. После отказа профиль равен исходному. Успешный повтор списывает ровно один бесплатный кредит; Classic закономерно получает assisted=true. Ни поле, ни лоток, ни RNG, ни счёт от подсказки не меняются. Подмена Worker контролирует сбои, успешный повтор считает настоящий worker.

## 2. Replay при ненулевом счёте

Это повторное воспроизведение известной ошибки из переданного `PREPLAY_READY_2026-11-07.md`, а не новое открытие. В доступной GitHub-версии она оставалась: createProfile(checkpoint) создавал best=0, validProfile отвергал best < score.

При проверке отдельного checkpoint синтетический best равен его score. Состояние игры не меняется; остальные проверки типов, геометрии, revision и правил сохраняются. JSON 0.46 не требует конвертации.

Четыре новые unit-регрессии сначала провалились на прежнем replay с Invalid checkpoint, после правки прошли. Покрыты старт посреди партии, resume после незаписанного хода, revive при ненулевом счёте, повреждённая геометрия и независимость экспортированной копии. Промежуток выключенной записи исключается из интервалов зарегистрированных решений; revive остаётся границей сегмента.

## 3. Версия в аналитике и диагностике

Найдено расхождение метаданных: ProductAnalytics и PerformanceCapture сообщали 0.31, PlayCapture — 0.46. Добавлен общий APP_VERSION; unit-тест сверяет его с Android versionName. Browser-имена JSON используют ту же версию. SchemaVersion форматов не меняется. При сборке 0.47 необходимо обновить APP_VERSION вместе с versionName; тест не позволит молча разойтись.

## 5. Запуск уже скрытого приложения

Дополнительный сценарий после полного прогона: document.hidden=true ещё до загрузки приложения, затем visibilitychange и обычный ход. На исходном коде браузер воспроизвёл Boot failed ReferenceError: Cannot access dragFrame before initialization. Начальная установка visibility-blocker вызывала остановку до инициализации локального состояния переноса. В новом коде таймер подсказки также должен быть инициализирован до этого обработчика.

Состояние dragFrame/dragSample/hintTimeout перенесено перед подключением жизненного цикла. После исправления сценарий проходит: игра запускается, возвращается из скрытого состояния и принимает ровно один ход. Повторный целевой прогон 16/16 (12 отказов подсказок, новый запуск в фоне, три stability-сценария) прошёл. Это браузерная модель исходного hidden, не запуск физического Android в фоне.

## 6. Синхронизация старых визуальных проверок

В облачных запусках 26a32d8 проявились падения старых сценариев: push 42365279703 — festival pause=true и tile-material series 20; PR 42365283594 — preflight haptics. Эти результаты не скрываются успешным локальным прогоном.

Найдены и исправлены несогласованные ожидания в тестах: festival замораживал RAF сразу после resize до подтверждения выбора фигуры; tile-material читал спрайты сразу после async-сохранения второго хода, до следующего draw; preflight устанавливал синтетические часы посреди уже запущенной анимации счёта. Теперь выбор явно подтверждается, сохранение/отрисовка ожидаются отдельно, часы устанавливаются до создания игровых таймеров. Ожидаемые очки, текстуры, лимиты пула и отсутствие лишних haptics не ослаблены; retries не добавлены.

Festival/tile-material проверены в трёх последовательных повторах: 15/15. После дополнительного переноса установки часов: preflight 12/12 (4 сценария × 3 повтора), festival 6/6 (2 сценария × 3 повтора). Это исправления испытательного стенда, а не доказанный выигрыш FPS или новая режиссура очисток.
