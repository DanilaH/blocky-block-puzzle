## Кандидат и проверка

- Использовать действующий goal generator/search/worker, а не второй движок. Сначала структурные matched-ситуации на одинаковых полях; затем реальные model rollout по действиям разных ботов.
- Разнообразие старта и отбор задач — два фактора. Предусмотреть frozen offline ablations: control / только старты / только задачи / полный кандидат. Абляции не являются дополнительными кандидатами для выбора лучшего по holdout.
- Обычные линии, доступные награды, ранние поражения, сильные/неточные игроки, censored tail и стоимость поиска — отдельные guards. Численные пределы выбрать по baseline, не по результату кандидата. Сохранять общий work≤24000 и независимый legal fallback.
- Защищённые revive и техническая неизвестность имеют приоритет над фазой. Не продлевать protection hysteresis и не выдавать неизвестную задачу за доказанную.
- Если используется темп, брать только подтверждённое активное время: без pause/background/fullscreen ads/загрузки/blocked input/save. Записывать входы для replay; missing time не равно низкому skill. Не делать сложнее от одного быстрого drag.
- Старты: сохранить старый composition-v2, новую самостоятельную версию и историю anti-repeat по структуре/первому решению. Resume не меняет поле или контент. Не давать постановочный all-clear каждому старту.
- Перед APK: unit, старые1120 exact/independent moves, worker/cancel/atomic-save/replay, 320/390px текущего dropdown, Android/signature/packaged resources. Preview demo ads, analytics OFF.
- Новый режим manual/HOLD, rollout OFF, defaultv2. Даже успешный model/CI не закрывает человеческую осмысленность и телефон. При наградном/корректностном провале — HOLD/REJECT, не скрывать данные.

Revive window0/1/2, рекламные shields/cadence, кабинет и новый визуальный стиль вэтот P1-B не входят. Плейтест0.69 можно проводить параллельно.

Gates для открытия holdout, затем те же для holdout:

1. Все witness разыгрываются независимыми клетками; ни одного ложного CHAIN/CHOICE/превышения production work. All-off A/A, save/replay,1120 legacy moves и3 revive recovery — точное совпадение. UNKNOWN никогда не отрицательное доказательство.
2. Для tasks против control и full против starts: после36 ходов доля независимо найденных CHAIN или CHOICE растёт минимум на max(1 процентный пункт,20% контрольной доли). В сумме focused matched-полей есть ≥1 действительно новый CHAIN и ≥1 CHOICE относительно v2 на том же входе. Иначе цель контента не выполнена, даже при зелёных тестах.
3. По каждому стилю: доля обычных ходов с линией ≥85% соответствующего контрольного фактора; для clear/three/lapse доля all-clear ≥75%; bounded число партий с наградой уменьшается максимум на1 из8. В кандидатах не более1 дополнительного поражения до/на36 ходе на8 запусков. Средняя capped длина clear/lapse не растёт более10%. Эти пороги — guard для этой малой модели, не отраслевые нормы.
4. Fallback не выше2×контроль+1 на8 партий каждого стиля. Production work≤24000 (старты≤512). p95 generation wall time≤1.25×control+2ms; serial desktop CPU, не phone FPS. Контекст ограничен8 длительностями и3 opening keys; ни одного роста в зависимости от длины партии.
5. Первые12 контрольных выдач и earned recovery не меняются от task focus; существующие награды выше приоритета окна. Ни один стартовый witness не вызывает all-clear; вся тройка разыгрывается при32 вращениях; resume и ошибка сохранения не расходуют историю.

В отчёте сохранять отдельные результаты обоих сравнений и всех факторов, даже при неуспехе. Dev-failure закрывает holdout; исправление причины требует нового freeze/поколения, не подбора по holdout. Успех gates разрешает техническую поставку manual/HOLD, не смену default и не rollout.
