# Короткая Performance-трасса реального WebView

08.11.2026. Нужны POCO с установленной0.51 и компьютер с Chrome/USB-соединением. Удалять игру, менять WebView или ставить новую APK не требуется. Наличие доступного телефона/USB пока не подтверждено. Отладка включена в проверенном debug APK и конфигурации Capacitor; это проверка исходников/manifest, не состоявшегося подключения.

1. Включить на телефоне режим разработчика и отладку по USB. Подключить его к компьютеру кабелем с передачей данных и подтвердить запрос авторизации на телефоне.
2. На компьютере открыть `chrome://inspect/#devices`, включить Discover USB devices. В открытой на телефоне игре найти WebView приложения Blocky Preview / com.danilah.blocky.dev и нажать Inspect. Если он не появился — остановиться на настройке подключения; не менять GPU/WebView-флаги наугад.
3. В DevTools открыть Performance. CPU — No throttling, network — No throttling. Screencast и запись Screenshots выключить. Не включать расширенное paint instrumentation в первый замер, чтобы не создавать лишнюю нагрузку.
4. На телефоне заранее включить обычную «Записать плавность игры» и дать уведомлению исчезнуть. На компьютере нажать Record **без перезагрузки** страницы. На телефоне выполнить одну полную очистку с лагом, подождать около3с и поставить игру на паузу.
5. На компьютере остановить запись и сохранить Performance profile/trace. Затем на телефоне выгрузить обычный blocky-performance JSON. Передать оба файла: короткую трассу с одним событием и соответствующий JSON с точной позицией.

Разбор: сопоставить pointer/input событие, подтверждение хода и последующее визуальное окно; оценить scripting/style/layout/paint/composite, scheduler gaps и доступные GPU/commit waits. Не складывать вложенные длительности. Не выводить работу GPU только из времени JavaScript; отсутствие GPU track не означает отсутствия GPU-ограничения. Трасса с подключённым debugger имеет собственный overhead, поэтому служит прежде всего локализации причины, а не новому FPS-бенчмарку.

Если remote Performance profile не раскрывает системное ожидание, следующий уровень — короткая Android/Perfetto system trace, привязанная к тому же событию. Это отдельный следующий шаг после просмотра первой трассы; полный bugreport заранее не нужен.

Основания: [официальное подключение WebViews](https://developer.chrome.com/docs/devtools/remote-debugging/webviews), [Performance reference](https://developer.chrome.com/docs/devtools/performance/reference).
