# Лаг очистки: сравнения и диагностическая 0.49

07.11.2026. Продолжение физического замера 0.48 на POCO M6 Pro. Цель — устранение лага полной очистки, без отключения оформления обычной игры или снижения её разрешения.

## Итог этапа

Лаг ещё не исправлен. Ни один проверенный кандидат не принят в обычный рендер. Preview 0.49 предназначена для автоматического сравнения на физическом телефоне, где ранее зафиксирован rAF-интервал 92,5 мс. В неё также входит уже подготовленный более весомый отклик окончательного поражения.

Обычная отрисовка использует прежние четыре подсветки края. Экспериментальный кеш не создаётся при обычном запуске; он подготавливается только на отдельной странице замера. Flow-v4, счёт, сохранения и право revive не меняются.

## Стендовые сравнения

208 эпизодов. 44 с ошибкой wrapper не используются для приёмки; остальные 164 включают разведочные прогоны и отдельные подтверждающие серии. SwiftShader / Chromium 141, не GPU телефона. UA Android меняет выбор Phaser texture units, но не аппаратную платформу. Последние подтверждающие прогоны: viewport 392×872, DPR 2,75, canvas 1024², effective texture units 1, production build, 3 контекста × 2 повтора, окно 2200 мс. Порядок условий развёрнут во втором контексте.

Две реальные сохранённые позиции дают 2298 и 19470. Третья синтетическая позиция соответствует только числу линий/серии/all-clear из аппаратного файла (три строки, серия 1), а не неизвестным фигурам/теме того эпизода. Контроль оформления в стенде 0→5, праздник 2.

| Кандидат | Результат | Решение |
|---|---|---|
| Один startup-атлас четырёх VFX | Меньше draw calls, устойчивого улучшения rAF нет | Отклонён |
| Discard нулевого alpha в shader | Выигрыш не показан; установка shader addition отдельно не зафиксирована в том пакете | Не принят, вывод об эффективности ограничен |
| Тесные границы всех SpriteInk frames | Небольшой выигрыш, но до 20 уровней отличия на мелких сглаженных контурах | Отклонён |
| Native trim только больших nine-slice | Малые контуры сохранены; выигрыш слишком мал во 2/3 позиций | Отклонён |

Граница приёмки перед соответствующими новыми подтверждающими прогонами: ≥10% снижения медианного числа интервалов >25 мс на каждой позиции, отсутствие большого регресса отдельного тёплого повтора и холодной медианы, совпадение исхода хода. Это производственный инженерный порог, не статистическое доказательство. Планы и hashes лежат в lag-049; ранние разведочные результаты не объявляются зарегистрированными заранее.

### Исправление измерительного стенда

Первый screen и первая confirmation-серия кеша (8 + 36 эпизодов) оказались невалидны: диагностический wrapper SpriteInk.image не передавал новый необязательный texture key. Обычная игра и отдельные pixel-тесты этого wrapper не используют. Эти цифры исключены. Wrapper теперь передаёт key и немедленно сообщает об отсутствующем frame. Критерий не смягчён; последующие 36 + 36 эпизодов используют исправный путь. Отмеченное в промежуточном сообщении ускорение 12–17% не является итогом приёмки.

## Аппаратный автозамер

Путь: «Пауза → Ещё настройки → Диагностика → Автозамер очистки». Отдельная страница в том же APK/WebView. Пользователь нажимает «Начать замер» и оставляет экран открытым около 70 секунд. Затем «Сохранить замер» и «Вернуться в игру».

Синтетическая тройная очистка, неизменные фигуры/состояние для всех условий. Кеш рамки сначала прогревается; warmup сохраняется отдельно. Затем семь условий проходят дважды в прямом/обратном порядке: исходник, экспериментальная рамка, без SpriteInk, без VFX, без внешнего праздника, без ambient, без смены темы. Отсутствующие слои — намеренная диагностическая картинка; они не предлагаются как исправление.

2100 мс между эпизодами дают закончиться возврату материала, затем 2400 мс измерения. Вариант кеша заранее подготовлен до замеров. Сохраняются rAF, фазы boardDraw, markers themeReveal/allClearFestival, long tasks при поддержке API, GPU renderer/vendor, пределы и фактический выбор texture units, viewport и canvas. Это не GPU timer и не полноценная партия с HUD, input, расчётом новой выдачи или сохранением: исследуется визуальная часть, для которой в исходном физическом замере начались поздние провалы.

Страница не импортирует IndexedSave/ProfileStore и не записывает тестовую партию. Текущая игра возвращается с тем же game state. Открытие страницы блокируется, пока не выгружены запись ходов или существующий замер плавности; неуспешный экспорт не снимает защиту. Background, resize, context loss и native appStateChange прерывают замер, не добавляя паузу в корректно завершённые результаты. Файл не отправляется автоматически.

## Ограничения кеша

Эксперимент заранее композитит только четыре одинаково окрашенные рамки. 64 уровня интенсивности, 8 quads вместо 32. Текстура 640², 1 638 400 оценочных RGBA-байт, плюс CPU backing и метаданные; создаётся один раз только в диагностике. Native trim убирает лишь полностью прозрачные texels, сохраняет два texel gutter и логические pivots. Мелкие исходные контуры не меняются. Кеш не заменяет остальные части праздника.

Предварительная композиция округляет alpha; сравнения охватывают шесть уровней энергии, WebGL 512²/1024² и Canvas 512². Во всех 18 случаях максимум ≤3/255 по каналу, среднее <0,05/255 по всем каналам. Это ограниченное отличие тонов, не побитовое совпадение и не физическая визуальная приёмка телефона.

## Проверки и артефакт

Локально build и 220 unit прошли. 18 pixel-сравнений прошли. 19 целевых ads/revive/result/benchmark-сценариев прошли: полный список профилей, JSON export, неизменная реальная партия при возврате, прерывание в фоне, защита записей и retry неуспешного экспорта. Production smoke с настоящими 2100/2400 мс завершил 14 профилей + warmup, без page/asset errors; финальный повтор и CI/APK проверяются.
