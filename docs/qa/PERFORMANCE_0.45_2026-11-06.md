# Preview 0.45 — оптимизация поля и эксперименты выдачи

## Выпущенное изменение

В Classic 64 неподвижные лунки вынесены из WebGL в повторяемый векторный CSS-фон. Цвет поля плавно следует теме, фон снимается при shutdown. Разрешение canvas (до 1024), текстуры фигур, эффекты и координаты переноса сохранены. Кампания использует прежнюю отрисовку. Выдача production остаётся flow-v4.

RenderTexture для свечения и непрозрачный canvas проверены и отклонены: устойчивого выигрыша не обнаружено.

## Производительность

Облачный Chromium, 390×844, DPR 2, ANGLE/SwiftShader (программный GPU). Подготовленная очистка трёх строк и трёх столбцов с последующим переносом фигуры. По три запуска контроля и итогового варианта.

| Вариант | p95 по запускам, мс | Кадры >33,4 мс |
|---|---|---|
| Контроль 0.44 | 50 / 50 / 49,9 | 31/208 (14,9%) |
| Итоговая сетка 0.45 | 49,9 / 33,4 / 33,4 | 22/236 (9,3%) |

Ранний CSS-прототип имел ошибку специфичности и скрывал сетку. Ошибка исправлена; его замеры не использованы в итоговой таблице. Проверены наличие grid background в computed style, DPR 3, прерванная смена тем, восстановление темы после reload и квадратное поле в landscape. Пиксели центра пустой клетки совпали с контролем; сетка присутствует. Отдельно записаны восемь подготовленных сцен от постановки до смены темы.

Это небольшой стендовый замер, а не доказательство стабильных 60 FPS на Android. Длительные кадры остаются. Нативная вибрация, реальная реклама и физический телефон не проверялись.

## Выдача: 228 симулированных партий

Диагностический скрипт `scripts/audit-dealer45.mjs` подменяет политику только в экспериментальном Vite transform. Production-алгоритм не изменён. Лимит 1200 ходов; партии, достигшие лимита, не считаются завершёнными. Стратегии imperfect, greedy и planner — алгоритмические приближения, а не реальные сегменты людей.

- wave: 24 разведочных партии, ограничение помощи в 6 из 18 выдач после первых 60 ходов.
- wave_dense: 24 партии, 9 усложнённых выдач из 18. Слабую стратегию ухудшает, сильной дополнительного ограничения не даёт.
- Парный holdout: 24 новых seed × 3 стратегии × baseline/wave = 144 партии.
- choice_wave: 36 партий, вместо снижения помощи расширяет выбор финалистов. Planner завершил поражением 2/12, как baseline; эффект управления сильным игроком не подтверждён.

### Парный holdout wave

| Стратегия | Поражения baseline → wave | Медиана ходов baseline → wave | Полные очистки baseline → wave |
|---|---|---|---|
| imperfect | 24 → 24 | 146 → 98 | 11 → 10 |
| greedy | 22 → 23 | 318,5 → 383 | 106 → 77 |
| planner | 2 → 5 | 1200* → 1200* | 574 → 349 |

*Медиана ограничена лимитом, фактическая продолжительность неизвестна. Первые 60 ходов совпали в парных прогонах. У planner частота полных очисток упала примерно на 35%, при этом большинство партий всё ещё дошло до лимита. У imperfect жизнь заметно сократилась. Этот компромисс не принят.

Все новые варианты отклонены для production. Следующая гипотеза — оценивать сложность доступных решений и управлять ею отдельно от силы помощи; прежде чем включать такую политику, нужны новые сравнения с сохранением наград, старта и поддержки после revive. Реклама не является входом выдачи, конверсия в revive этими симуляциями не измерялась.

## Повтор эксперимента выдачи

Из корня репозитория (Node 24, зависимости установлены):

```bash
SIM_VARIANT=wave SIM_SEEDS=24 SIM_OFFSET=100 SIM_LIMIT=1200 SIM_STRATEGIES=imperfect,greedy,planner SIM_OUT=/tmp/wave.json node scripts/audit-dealer45.mjs
SIM_VARIANT=baseline SIM_SEEDS=24 SIM_OFFSET=100 SIM_LIMIT=1200 SIM_STRATEGIES=imperfect,greedy,planner SIM_OUT=/tmp/baseline.json node scripts/audit-dealer45.mjs
```

Для разведочных wave/wave_dense/choice_wave: SIM_SEEDS=12, SIM_OFFSET=0; у первых двух использованы greedy,planner, у choice_wave также imperfect. Эти политики предназначены только для диагностики, не для подключения к сохранённым партиям.
