# Аудиофокус Android — 29.10.2026

## Изменение

Собственный Capacitor `BlockyAudioFocus`: AudioManager на main thread, AudioFocusRequest для API 26+, совместимый listener для API 24–25. Регистрация до загрузки bridge. Реализация написана для этого проекта; код kit не копировался.

Фокус запрашивается после явного звукового действия, только при активной игре и включённом звуке. `AUDIOFOCUS_GAIN` + `USAGE_GAME`/`CONTENT_TYPE_SONIFICATION`: сторонний плеер может остановить музыку. Это не режим совместного микширования. Включённая настройка сама по себе не запрашивает фокус при запуске. Пока сеанс активен, фокус удерживается между игровыми SFX; пауза, диалог, mute, реклама, фон и destroy его освобождают.

Любая потеря, включая duck, гасит голоса и delay, немедленно обнуляет master gain и приостанавливает Web Audio. Временный возврат разрешает новые звуки со следующего жеста; прежние хвосты не повторяются. Постоянная потеря не запускает борьбу за фокус при каждом тапе: повторный запрос возможен в следующем сеансе после паузы/возврата либо переключения mute. Отказ не блокирует игру. На API 26+ разрешён отложенный gain; на старых ОС отказ остаётся тишиной до нового сеанса.

Native generation отбрасывает callback уже освобождённого запроса. JS сериализует lifecycle-команды, проверяет поколение жеста и ревизию native-состояния. Отсутствующий listener приводит к тишине, а не работе без наблюдения потерь. При уже полученном фокусе bridge не вызывается на каждый тап.

`GameAudio` дополнительно защищён от завершения `resume()` после `stop()`: generation + unlocked + синхронное обнуление gain. Выключение звука теперь сразу обрывает уже звучащие хвосты. Отказ resume обработан.

## Основание

[Android Developers: Manage audio focus](https://developer.android.com/media/optimize/audio-focus) — просмотрено 29.10.2026. Учитываются проверка результата запроса, transient/permanent loss, отказ, abandon, API 24/26 и ограничение запроса из фона при target 35+. Foreground service и новые разрешения не добавляются. Web Audio остаётся движком звука; согласованность поведения WebView с AudioManager ещё требует телефона.

## Проверки

- Unit: прекращение хвостов при mute/loss, отсутствие replay после gain, отложенный resume после stop, отсутствие AudioContext при denied, устаревший granted-ответ после loss, пауза/возврат во время запроса, отказ bridge/listener, web fallback.
- Browser: mock native loss/gain при настоящем AudioContext, сохранение управления без фокуса, пауза не допускает unmute.
- Локально: 78 unit и 72 browser прошли; production build успешен. Первый web-прогон был нарушен редактированием dev-модулей (reload/navigation failures); повторный полный прогон на неизменном исходнике прошёл 72/72.
- CI 40879344281, verify job 123466369660: unit, build и browser прошли. Android job 123468293818 завершился успешно. Всего 150 автоматических проверок.

## Не проверено

Физический Android: звонок/ассистент/уведомление, другая музыка, отключение наушников/Bluetooth, rewarded/interstitial и возврат, API 24–25 и современный WebView. Сценарий отключения наушников отдельно ещё не обработан. Нет заявления о проверенном на телефоне звуке или итоговом feel. APK 0.17 этих изменений не содержит.
