# 0.59: исправление ложного отказа CDP-preflight

Владелец прислал ZIP остановившейся 0.58. Матрица не запускалась: 0 игровых эпизодов. Запись оказалась рабочей: 9 354 события, 15 Paint с node IDs, 507 GPU events, 6 native Draw, 376 flow endpoints; метаданные без ошибки и dataLossOccurred=false. Контрольный div backend node 181 имеет 6 собственных Paint. Его слой 105 присутствует в LayerTree с paintCount 1→2→3→4→5→6, но отдельного LayerTree.layerPainted в этой записи WebView 156 нет.

Причина: валидатор требовал layerPainted даже при одновременно записанных Paint нужного узла и растущем paintCount его собственного слоя. Он объявлял полноценные данные неполными и останавливал запуск. Это ошибка нашей проверки, не отсутствие поддержки записи на телефоне. [Сводка повторного разбора](full-clear-059/phone-preflight-replay.json). Приватный ZIP в git не добавлен.

## Исправление

- Связь известного probe с Paint остаётся обязательной: конкретный backend node либо его конкретный layer ID.
- Подтверждение отрисовки слоя: отдельный layerPainted либо увеличение paintCount между последовательными LayerTree-образцами того же drawsContent-слоя и backend node.
- Постоянный/убывающий счётчик, изменение чужого узла или Paint чужого элемента не проходят проверку. Проверки GPU/native flow, DOM/layers, ошибок, целостности и потери данных сохранены.
- Независимый Python-анализатор поддерживает те же два варианта доказательства. Архивы 0.58 остаются читаемыми; исходный неполный запуск не превращается в завершённый задним числом.
- Ошибка запуска показывает этап и исходное сообщение, тестовый элемент удаляется при любом исходе. Эти UI-правки были подготовлены после первого сообщения о сбое.
- Версия Android/web повышена до 0.59. Обычная игра, положение теста, 14 абляций и длительность измерений не меняются.
