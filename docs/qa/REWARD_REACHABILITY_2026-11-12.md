# D80 — на 31 позднем поле полная очистка за одну тройку невозможна

Основа — восстановленный локальный D79 `adfeced`, на D78 `c31a49e`.
C1 остаётся отклонённым. Новый генератор, коэффициенты, сохранения, default и
APK не менялись. Последняя рабочая сборка — 0.63/director-v2.

## Что установлено

На **всех 31 поздних инженерных полях C1/bounded** нет последовательности из
одного, двух или трёх размещений, которая полностью очистит поле. Это полный
перебор текущего каталога, а не промах ограниченного поиска.

Разрешены все 31 ориентация, повтор фигур, любой порядок, промежуточные очистки
и отсутствие ограничения площади. Такой поиск шире возможностей C1. Проверен
каждый инженерный deal с `12 <= move < final moves`: четыре seed
2441001–2441004, от 9 до 36 занятых клеток. Holdout D79 не использовался.

| Проверка | Результат |
|---|---:|
| Исходные поздние поля | 31 |
| Поля с all-clear за ≤3 размещения | 0 |
| Полный каталог допустимых размещений | 1 333 |
| Полный обратный индекс последнего хода | 18 399 состояний |
| Первые допустимые размещения | 12 648 |
| Допустимые двухходовые префиксы | 4 887 399 |
| Проверки fit основного поиска | 16 901 107 |
| Независимые прямые проверки последнего размещения | 3 050 202 592 |

Исходные поля, счётчики и SHA: [results.json](reward-reachability/results.json).
Независимый прямой перебор: [checks.json](reward-reachability/checks.json).

## Почему отрицательный результат здесь сильнее прежнего

D79 показал отсутствие найденной награды в пуле, затем две ограниченные пробы
ничего не нашли. Их результат оставался unknown. D80 проверяет другой вопрос:
существует ли награда за три произвольных размещения вообще.

Основной алгоритм точно перечисляет все стабильные поля, которые один ход
очищает целиком. После добавления фигуры заполненные клетки должны составлять
объединение полных строк и столбцов. Каждая очищаемая линия пересекает новую
фигуру: иначе она уже была полной до хода, что невозможно в стабильном поле.
Перебираются все такие пересечения, затем вычитается фигура. С этим полным
обратным индексом соединены все допустимые префиксы длины 0, 1 и 2.

Отдельный алгоритм не использует обратный индекс: он строит первые два хода,
объединяет одинаковые итоговые поля и напрямую перебирает каждое последнее
размещение. Он использует другую реализацию одновременной очистки. Все 31
отрицательных результата совпали. Ограничений beam и runtime budget здесь нет.

## Проверки алгоритмов

- 31 небольшой пример сопоставлен с независимым полным клеточным Python-поиском.
  Включены положительные горизонты 1/2/3, отрицательные случаи и последовательные
  промежуточные очистки. Проверяется наличие решения, а не снимок реализации.
- На семи положительных позициях полного каталога найдены 155 трёхходовых
  свидетельств. Каждое проверено отдельными клеточными правилами и публичными
  TypeScript `fits/place`: 465 размещений, 155 фактических полных очисток.
- 313 unit /49 файлов и production build прошли. Runtime и lockfile совпадают
  с D79/D78. Browser, worker и Android заново не запускались: игрового изменения нет.

Скрипты: [основной поиск](../../scripts/director/reward-reachability.cpp),
[независимый прямой поиск](../../scripts/director/verify-reward-reachability.cpp),
[клеточная проверка](../../scripts/director/verify-reward-reachability.py),

[Протокол](reward-reachability/protocol.md) фиксирует горизонт и границы вывода.

## Инженерное решение

**Не продолжать исправлять выдачу этих полей отбором очередной тройки ради
немедленного all-clear.** На них более умный ранжировщик, другой трёхходовый
построитель и увеличение CPU не могут создать такую награду. Ограничение
старого static cover<=4 не является единственной причиной промаха.

Если сохраняем цель периодического all-clear для неточных решений, следующая
ограниченная инженерная задача — восстановление геометрии за несколько троек:
доступные обычные очистки по пути и сокращение расстояния до большой награды
после разных разумных действий. Сначала показать такие маршруты и их ветвление
на инженерных позициях, потом проектировать выдачу. Точный будущий маршрут
не должен становиться единственным разрешённым поведением игрока.

Это направление, а не новый принятый C2. Не переходить автоматически к v7,
плану будущего лотка или фазовой машине. Локальная оценка геометрии тоже может
вести к восстановлению в нескольких последовательных выдачах. Её пользу ещё
предстоит проверить. Если ограничить награды только немедленным all-clear,
на таких состояниях поставлена математически невыполнимая задача.

## Чего результат не доказывает

- Не все поздние поля игры таковы: это 31 связанное состояние четырёх модельных
  партий отклонённого C1, не случайная выборка людей или director-v2.
- Невозможность за три хода не означает невозможность за четыре, шесть или позже.
  Точное расстояние за этим горизонтом не измерено.
- Наличие длинного пути ещё не означает, что игрок увидит и выберет его.
  Проверка доступности найденных наград на этих 31 полях не выполнялась: их нет.
- Необходимость глобального директора, приятность игры, длительность сессии,
  удержание и устранение POCO lag этим не установлены.
- Быстрый C++-поиск офлайн не является готовым TypeScript/Android генератором
  и не проходит автоматически общий runtime budget 24 000 операций.

Человеческое сравнение существующих flow-v4/v2 в APK0.63 по D78 остаётся открытым.

## Воспроизведение

Нужны Python3, C++17 `g++` и установленные зависимости проекта.

```sh
python3 scripts/director/reward-reachability.py
python3 scripts/director/verify-reward-reachability.py
node scripts/director/verify-reward-reachability.mjs
npx vitest run --maxWorkers=4
npm run build
```

Компилятор пишет исполняемые файлы только во временную директорию. В Git
сохраняются исходники, plain JSON и протоколы; содержимое файла не кодируется
в base64 и не передаётся частями. По просьбе владельца запрет blob workflow
добавлен в AGENTS.md.
