# Альтернативная отрисовка: изолированный прототип, 08.11.2026

Статус: исследовательская ветка, **не принято как исправление лагов**. Установленная0.54 и обычная ветка preview сохраняются. Новый APK пользователю не выдаётся: устойчивого выигрыша по длинным кадрам пока нет. Снижение отдельного счётчика Paint не закрывает gate плавности.

## Что действительно реализовано

1. `BoardBackdrop`: неподвижный рисунок сетки и два непрозрачных цвета; смена темы через прозрачность старого слоя вместо покадрового repaint background-color под живым WebGL. Перекрытие слоёв следует старой линейной интерполяции. Пауза завершает fade, shutdown удаляет слой; смена темы посреди fade берёт текущий математический цвет, без getComputedStyle в кадре.
2. Поверхность рисования отделена от существующей симуляции Festival/Atmosphere. Ограниченный WebGL batch рисует прежние команды, цвета, число частиц и траектории; изображения один раз собираются в атлас. Это не перенос правил/очков/RNG и не упрощение эффектов. Обычный прототип использует GPU только для Festival, Atmosphere сохраняет Canvas2D. Прямые normal/screen premultiplied blends, проверка потери/восстановления контекста, Canvas2D fallback при отказе GPU.
3. Дополнительный контроль: общий драйвер декоративных canvases после Phaser postrender, вместо отдельного RAF. Этот путь также не принят по плавности. До принятия нужно отдельно подтвердить количество реально нарисованных кадров эффектов: улучшение за счёт более редкой анимации не допускается.
4. Запущена та же игровая позиция на Phaser3.90.0 как **исследовательский runtime alias**, без изменения package.json/lockfile. Исправлен только диагностический доступ к metadata renderer в контроле. Переход на другую версию движка не принят: нет достаточного устойчивого выигрыша; пиксельное совпадение семантики ADD между major-версиями не установлено.

## Стенд и границы

Linux Chromium/software graphics,392×872,DPR2.75, mobile emulation. В финальном сравнении пакета и движков — Android/WebView UA и подтверждённый один texture unit Phaser. Основной canvas1024²; на POCO из последнего ZIP896². Везде одна и та же позиция:121→1574, две колонки, пустое поле, тема1→5. Косметический RNG фиксирован на стенде; исходные игровые расчёты/сохранения остаются настоящими.

Во всех эпизодах CDP tracing активен, включая эпизод с унаследованным названием untraced. Не трактовать его как обычный телефонный untraced. Каждый named span суммируется отдельно; вложенные события не складываются как независимые затраты. Canvas2DBitmapProvider::Snapshot не регистрируется этой Linux-версией Chromium даже в Canvas2D-контроле; ноль событий не доказывает отсутствия работы и не сравнивается с8774 событиями физической0.54.

## Измерения и решения

- Перенос обоих внешних слоёв в отдельные WebGL-контексты ухудшает software-результат: untraced >25мс20→27 в разведке. Как интеграция отклонён. [Все четыре варианта](render-refactor-study/surface-recon.json).
- Отдельный Festival и вариант без MSAA проверены, устойчивого выигрыша не получено. [Контроли](render-refactor-study/surface-noaa-recon.json). Отключение MSAA не принято как визуальная/производительная правка.
- Только composited bed: Paint17.197/16.307мс у контроля против10.069/10.048мс, но длинные интервалы не улучшаются устойчиво. [Пары](board-backdrop/comparison.json).
- Полный первоначальный пакет (bed + Festival GPU), Android UA: untraced >33.4мс6/9 у контроля против4/7 у кандидата; max50/50мс против50.1/50мс. Это смешанный, недостаточный результат. [Сравнение](render-package/comparison.json).
- Пакет после устранения per-sprite JS allocations: untraced >33.4мс2/6 против7/9; >25мс13/12 против18/17. У traced смешанный результат. Gate не пройден. [Новые данные](render-refactor-study/package-optimized.json).
- Phaser4/3/3/4, по одному texture unit: untraced >25мс12/14 против7/13, >33.4мс5/4 против3/5. У первого Phaser3 max50мс против33.4/33.5мс у контроля. Поэтому первоначальный хороший одиночный прогон Phaser3 не означает готового решения. [4a](render-refactor-study/engine4-first.json), [3a](render-refactor-study/engine3-first.json), [3b](render-refactor-study/engine3-second.json), [4b](render-refactor-study/engine4-second.json).
- Общий frame driver: untraced >25мс14/21 против15/13; traced16/14 против12/15. Нет устойчивого крупного выигрыша; частота фактической анимации не измерена и требует отдельного gate. [Данные](shared-clock/comparison.json). Первый контроль частично совпал с концом функциональной проверки: его абсолютные времена не использовать для подтверждающего performance-вывода.

Ранний GPU-прогон, во время которого изменился исходный модуль, и попытка package-probe с отсутствовавшим методом finish у контрольного адаптера исключены. Они не включены в приведённые валидные пары.

## Проверка изображения и поведения

Для GPU-кандидата проверены три постановки и350/900/1700мс. Состояние всех частиц совпало во всех9 парах. Среднее отличие по каналу0.0095–0.0852/255; максимум119 на отдельных границах, доля каналов с разницей>25 не превышает0.033%. Это **не** побитовое совпадение: AA/texture sampling разных растеризаторов отличается. Просмотрены парные изображения дождя/света; видимых потерь частиц/смены траектории нет. [Метрики](effect-surface/visual-comparison.json), [скрипт](../../scripts/qa-effect-surface.mjs). PNG промежуточной проверки не включены в обычные игровые ассеты.

BoardBackdrop: две смены цвета, пять промежуточных фаз, max difference≤4/255 и mean<0.8/255 в browser-test. Premultiplied normal/screen проверены по внутренним пикселям с допуском3/255. Во время20 повторных draw нет новых texture uploads. Resize/resume сохраняют backing588×1308 в портрете. GPU loss/restore возвращает подготовленную текстуру; отказ GPU сохраняет Canvas2D и110 частиц.

221 unit, assets:check и production build прошли до добавления общего clock driver. 7 целевых surface/backdrop/viewport browser-тестов прошли. 21 функциональный сценарий Classic/награды/сохранения/материалы/ориентации/диагностика/context recovery прошёл до принятия clock-кандидата; после добавления driver повторно прошли221unit, production build и14 browser-сценариев поверхности/подложки/resize/полного теста очистки/паузы/context recovery. Полный релизный browser/Android/физический gate не закрыт.

## Воспроизведение контроля движка

`probe-phaser-renderer.mjs` использует только временный alias из `/tmp/blocky-phaser3-control/shim.mjs`; обычная dependency остаётся Phaser4.2.1. Контрольный официальный npm tarball phaser3.90.0 SHA256:`c4e3a8da498ab94aa8859c7a32cb89140d94bfd95d769bee36a98cdef1bea6e6`. Подготовка: npm pack точной версии в этот каталог, извлечь package/dist/phaser.esm.js и создать shim с `import * as Phaser from './package/dist/phaser.esm.js'; export default Phaser;`. Запуск с PROBE_PHASER=3/4, PROBE_MAX_TEXTURES=1; данные задаются PROBE_OUTPUT. Исходный tarball/движок в репозиторий не копируются.

## Приёмка следующего исправления

Цель владельцу сформулирована как минимум вдвое меньше интервалов>33мс без ухудшения максимальной задержки, сохранение картины/числа частиц/разрешения и обычного игрового цикла. Это целевой критерий **физического** сравнения, он здесь не пройден. Исследовательские реализации остаются отдельно от обычной preview. Ни один результат выше не даёт основания объявить лаг исправленным или раздавать очередную сборку как ускорение.

Если продолжать локализацию, следующий полезный физический эксперимент — один автоматический capture с крупными отключениями при **настоящем текущем scripted clear**, а не ещё один APK на каждую микрогипотезу: board ink, board VFX, внешний Festival, atmosphere, reward DOM/theme. Старый70-секундный benchmark не подменяет его: он ранее не воспроизводил эту смену темы. Это следующий протокол, не уже созданная/выпущенная функция.
