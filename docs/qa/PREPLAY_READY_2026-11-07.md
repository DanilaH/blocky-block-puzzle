# Граница автоматической проверки перед плейтестом — 07.11.2026

Рабочая сборка: **0.46.0-preview / flow-v4**. Новый адаптивный директор не принят и не включён. Изменения этого прохода относятся к офлайн-разбору и тестам; новый APK не нужен.

## Исправление

`replayRecord` проверял checkpoint через `createProfile`, создающий профиль с рекордом 0. При ненулевом счёте это нарушало правило `best >= score`: корректная запись, начатая посреди партии, возобновлённая после пропущенных ходов или содержащая revive, отклонялась как `Invalid checkpoint`.

При проверке изолированного состояния игры синтетический рекорд теперь равен её счёту. Проверка геометрии, типов, допустимых ходов и остальных инвариантов сохранена. Старые JSON из APK 0.46 подходят без конвертации.

Добавлены регрессии: возобновление после незаписанного хода с исключением перерыва из времени решения; revive с ненулевым счётом и отдельным сегментом; начало посреди партии и отказ для повреждённого поля. Экспорт не позволяет изменять внутреннюю запись через возвращённый объект.

## Проверки

- 204 unit-теста пройдены; TypeScript/Vite build пройден.
- CLI `analyze.mjs` обработал синтетическую запись, начатую после первого хода: один зарегистрированный ход, один сегмент, прирост 6 очков. Это проверка тракта, не человеческий плейтест.
- `assets:check` пройден: alpha, trim, gutters и заявленные бюджеты ассетов.
- Полный браузерный прогон: 130/130 пройдено. Включает запись/экспорт, неуспешное сохранение, revive/таймер, повторные рекламные callbacks в тестовом адаптере, восстановление, touch/drag, смену темы и ограничение эффектов.
- Первый запуск браузерных тестов не дошёл до приложения из-за отсутствующего Chromium. Браузер установлен, запущен повторный полный прогон.
- По коду: расчёт refill flow-v4 выполняется в отдельном worker; pointermove объединяется через requestAnimationFrame; запись не вызывает solver и не расходует RNG. Это не измерение FPS устройства.
- Android APK, подпись и совпадение production-файлов проверены ранее: [протокол 0.46](PLAY_CAPTURE_0.46_2026-11-06.md). Этот проход не является повторной физической проверкой Android.

## Следующие данные, которые действительно изменят решение

Достаточно начать с 2–3 обычных партий; это качественная диагностика, не статистическая приёмка баланса.

1. В 0.46 открыть паузу → дополнительные настройки → запись партии для разбора → начать. Желательно до первого хода новой партии.
2. Играть обычным способом. При заметном повторе, скуке или неожиданном тупике запомнить примерный счёт/номер хода. Не подыгрывать помощнику специально.
3. Если появился revive, проверить один раз принятие, другой раз истечение таймера. Доступность реального rewarded зависит от рекламной конфигурации.
4. До закрытия приложения остановить и экспортировать JSON. Запись находится в RAM: закрытие процесса её теряет. Сохранение самой партии — отдельный механизм.
5. Для просадки отдельно включить диагностику производительности и экспортировать её; указать модель телефона и режим эффектов. Видео со звуком поможет оценить субъективный ритм и визуальные события.

Обработка записи: `node scripts/calibration/analyze.mjs input.json report.json`. Расхождение с ботом — повод посмотреть ход, не автоматическая ошибка игрока. Незарегистрированный промежуток и revive являются границами сегментов, не выдуманными ходами.

После данных выбираем один конкретный дефект выдачи, воспроизводим его на исходном seed/состоянии, сравниваем исправление с flow-v4 и вновь проверяем независимые траектории. До этого баланс заморожен.
