# Preview 0.52 — короткая диагностика без USB

## Задача и результат

USB-подключение POCO зависло на авторизации, пользователь отказался продолжать настройку. Добавлен запуск 15-секундной проверки из APK и отправка одного ZIP. Это сбор данных, **не исправление лага**. До получения файла с физического POCO причина задержки остаётся открытой.

## Что запускается

«Пауза → Ещё настройки → Диагностика → Проверить очистку · около 15 секунд → Начать проверку». Три одинаковые очистки: warmup, обычный захват rAF/фаз, захват с нативной трассировкой последнего повтора. После окончания — «Отправить результат».

Используются **настоящие Classic UI/commit/worker/IndexedDB/DOM rewards/BoardScene/Atmosphere/Festival**, не старая отдельная страница с уменьшенным полем. Размер поля и canvas рассчитывается обычной игрой. Прозрачная блокировка ввода во время прогона не меняет layout. Профиль теста хранится в отдельной `blocky-clear-trace`; `blocky-classic` и его backup не записываются. Возврат открывает прежнюю партию.

Фиксированная позиция взята из последней полной очистки POCO0.51: L3-3 в (6,0), столбцы 6/7, счёт121→1574, серия2, оформление1→5, вариант2, без нового рекорда. Полная предыдущая сессия не воспроизводится: в частности, нет предшествующей очистки за1482.8мс. Звук/вибрация отключены, native ads и product analytics не подключаются в этом режиме. Обычная выдача/визуальные эффекты не изменены.

## Трасса Android

Preview/debug на AndroidAPI28+ использует встроенный `android.webkit.TracingController`, без новых зависимостей, разрешений, root и USB. Категории ANDROID_WEBVIEW + JAVASCRIPT_AND_RENDERING + blink.user_timing; User Timing marks `blocky-clear:traced:{start,committed,end}` позволяют найти ход. На запись ставится нативный watchdog25сек, при фоне/destroy она останавливается. Приложение прекращает только собственную запись; чужую не перехватывает.

`stop()` сбрасывает JSON на отдельном executor. Результат доступен после закрытия output stream. До32MiB на диске; превышение/ошибка записи помечаются и неполная трасса исключается из ZIP. ZIP содержит `report.json`, `native-status.json` и, при успешной записи, `webview-trace.json`. Экспорт без поддержанной трассы всё равно содержит причину отказа и измерения игры. Файл отправляется только по явному нажатию через Android share sheet.

Источники API: [TracingController](https://developer.android.com/reference/android/webkit/TracingController), [TracingConfig](https://developer.android.com/reference/android/webkit/TracingConfig).

## Ограничения измерения

- Трассировка сама нагружает устройство. Сравнивать её FPS с untraced как выигрыш/регрессию оптимизации нельзя.
- RECORD_UNTIL_FULL имеет внутренний ограниченный буфер WebView; даже целый JSON может не содержать хвост. Проверять наличие всех marks и конечных времён перед выводами.
- Отсутствие GPU events не доказывает отсутствие GPU-проблем. Это не системный Perfetto со всеми процессами/счётчиками.
- API lifecycle, файл и share sheet пока не проверены на физическом POCO. Browser-проверки этого не заменяют.
- Если этот короткий прогон не воспроизведёт лаг, нельзя объявлять проблему исправленной: следующий шаг выбирать по трассе и разнице с реальной сессией.
